## 1️⃣ 背景: なぜ今このセキュリティ情報が公開されたのか

JPCERT/CCは2026年6月11日、ブログ「ツール分析結果シートのアップデート」を公開した。同シートは2017年に初めて公開されたもので、ネットワークに侵入した攻撃者が悪用する可能性の高いツールを実行したときに、Windowsに記録されるログを調べた結果をまとめている。原典は、Windowsの防御機構が高度化する一方で攻撃者の手法やツールも進化し、Active Directory（AD）環境の侵害が続いているという認識を示したうえで、「AD環境の変化や攻撃者の手法・使用するツールの変化を踏まえ」てアップデートしたと述べている。今回の更新ではWindows 11（version 24H2）とWindows Server 2025を対象に加え、対象のツールとコマンドを拡充した。初版の公開から環境と攻撃の両方が変わったことが、更新の背景にあると読み取れる。

---

## 2️⃣ 目的: JPCERT/CC が誰に何を届けたいのか

原典によれば、ツール分析結果シートの目的は、攻撃を受けたときにツールの実行に伴ってログに残る痕跡を確認・分析できるようにすることである。対象は、攻撃者が悪用する可能性が高い60個のコマンド・ツールで、イベントログ（監査ポリシーの有効化が必要）、実行履歴、Prefetch、Sysmonログなどの痕跡を調べている。原典はPWDumpXを例に、イベントログ「セキュリティ」でイベント ID: 4663が見つかり、PWHashes.txtというファイルが一時的に作られた痕跡があった場合、その文字列でシートを検索すると、PWDumpXの実行時に作られるファイルであることが分かると説明している。実務では似た痕跡を残す別のツールもありうるため、シートは実行されたツールの候補を絞り込む手がかりとして使い、ほかの痕跡と突き合わせて確かめるのが適切と考えられる。対象ツールは、コマンド実行、パスワード・ハッシュの入手、通信の不正中継、リモートログイン、権限昇格、ドメイン管理者権限アカウントの奪取、情報収集、ローカルユーザー・グループの追加・削除、ファイル共有、痕跡の削除の10カテゴリに分類されている。また、JSONファイルも公開し、機械的な活用や検索をしやすくしている。

---

## 3️⃣ 期待される効果: 業務にどう活かすか

原典は「ツール分析結果シートがインシデント調査に少しでも役立てば幸いです」と述べており、実務でのインシデント調査の質を上げることが期待される効果である。最新のWindows環境でログを調べた結果が加わったことで、新しい環境での調査にも使いやすくなる。JSON形式での公開により、検知ルールづくりやログ分析基盤への取り込みにも使えると考えられる。原典はさらに「今後さらに悪用されたツールおよびコマンドの検知方法などについても検証を進める予定」としており、継続的な改善も見込まれる。原典は2017年に検証したツールについても、Windows 7からWindows Server 2025までの各OSでの動作可否を記載しており、古い環境と新しい環境が混在する組織でも参照しやすい。

## 4️⃣ 3 ペルソナ別 実務シナリオ翻訳

同じ脅威情報も、立場が違えば「最初に取るべき行動」 が変わります。**本稿の核心は、ここから先の「誰に何を伝えるか」 の翻訳設計** にあります。

### ペルソナ① 現場担当者

**この立場の方が抱える懸念**: インシデント発生時に攻撃者がどのツールを使用したかを、Windowsのイベントログやファイル痕跡から迅速に特定できるかが気になる。

**明日から取れる 4 つの行動**:
1. JPCERT/CCのツール分析結果シート（https://jpcertcc.github.io/ToolAnalysisResultSheet_jp ）をダウンロードまたはブックマークし、インシデント対応時にすぐ参照できるようにする。
2. 調査対象端末のイベントログ（セキュリティ、Sysmon等）から特徴的なイベントIDやファイル名を抽出し、シートで逆引きして該当ツールの候補を絞り込む。
3. JSON形式のデータを自組織のSIEMやログ分析基盤に取り込み、既知の攻撃ツール実行痕跡を検出するルールの作成に活用する。
4. Windows 11（24H2）やWindows Server 2025環境でのログ出力の差異をシートで確認し、自組織のOS構成に応じた調査手順を整備する。

**この情報から学べること**: 原典では、60個のツール・コマンドを10カテゴリ（コマンド実行から痕跡の削除まで）に分類している。攻撃者が侵入後にどの段階でどのツールを使うかを体系的に理解することが、実効性のある調査の土台になる。イベントログやPrefetch等のWindows標準機能で取れる痕跡を把握しておくことで、調査の初動を速められる。

### ペルソナ② 管理者

**この立場の方が抱える懸念**: チームのインシデント対応能力が最新の攻撃手法に追随できているか、また検知ルールが最新OS環境に対応しているかが気になる。

**明日から取れる 4 つの行動**:
1. ツール分析結果シートの更新内容（追加ツール、対応OS拡充）をチームに共有し、自組織の検知ルールや調査手順を見直す対象を洗い出す。
2. JSON形式データを活用して、SIEMの検知ルールを最新のツール痕跡に更新し、検知カバレッジの拡充を現場担当者に指示する。
3. Windows 11およびWindows Server 2025への移行状況を踏まえ、インシデント対応手順書の対象OS記述をアップデートする。
4. 現場担当者のシート活用状況と検知ルール更新の進捗を定期的に確認し、組織のインシデント対応成熟度の向上を管理する。

**この情報から学べること**: 原典は、2017年の初版以降も攻撃者の手法とツールが進化し、AD環境の侵害が続いていると述べている。検知ルールや調査手順を固定したまま運用するのではなく、公的機関のリソースが更新されたことをきっかけにチームの対応力を見直す仕組みを整えることが管理上の責務になる。現場のシート活用結果と検知ルールの更新状況を集約し、経営層へ報告できる状態を保つことが管理者の役割である。

### ペルソナ③ 経営者

**この立場の方が抱える懸念**: 攻撃手法の進化に対して組織のインシデント検知・対応体制が十分に投資されているか、また公的機関が提供する無償リソースを有効活用できているかが気になる。

**明日から取れる 4 つの行動**:
1. JPCERT/CCのような国内の信頼できる公的機関が提供する無償リソースの活用状況を管理者に確認し、セキュリティ投資の効率化に活かす。
2. AD環境の侵害が継続しているという現状を踏まえ、SOC/CSIRTへの検知ルール更新やインシデント対応訓練への投資が適切かを判断する。
3. Windows 11やWindows Server 2025への移行計画と連動して、セキュリティ対応体制の整備状況を管理者から報告させる。
4. 管理者から検知ルール更新の進捗と対応成熟度の報告を定期的に受け、組織のインシデント対応力が攻撃の進化に追随しているかを経営レベルで把握する。

**この情報から学べること**: 原典では、JPCERT/CCが今後もツール・コマンドの検知方法の検証を進めると述べている。こうした公的機関の継続的な取り組みを活用することは、自組織単独では困難な脅威情報の収集・分析を補完する手段であり、経営層はその活用を支える体制への投資を支持する姿勢が求められる。セキュリティ対策は一過性の投資ではなく、攻撃手法の進化に追随する継続的な取り組みであることを理解し、管理者からの報告を経営判断に反映することが重要である。
